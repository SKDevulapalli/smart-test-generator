How to Write Test Cases

Kade Test Gen understands various formats for test case requirements. Here are the supported formats and best practices for writing effective test cases.

Gherkin/BDD Format (Recommended)

The most reliable format for UI and integration tests:

Feature: User Login

Scenario: Successful login with valid credentials
  Given the user is on the login page
  When the user enters username "testuser@example.com"
  And the user enters password "SecurePass123"
  And the user clicks the login button
  Then the user should be redirected to the dashboard
  And the welcome message should display "Welcome, testuser"

Test Case Format

A structured format for explicit test steps:

Test Case: Verify User Registration
Preconditions:
  - User is not logged in
  - Registration page is accessible

Test Steps:
  1. Navigate to /register
  2. Enter "John Doe" in the name field
  3. Enter "john@example.com" in the email field
  4. Enter "Password123!" in the password field
  5. Click the "Register" button

Expected Results:
  - User account is created
  - Confirmation email is sent
  - User is redirected to welcome page

API Test Format

For REST API test generation:

API Test: Create User Endpoint
Endpoint: POST /api/users
Headers:
  - Content-Type: application/json
  - Authorization: Bearer {token}

Request Body:
{
  "name": "John Doe",
  "email": "john@example.com",
  "role": "user"
}

Expected Response:
  - Status: 201 Created
  - Body contains "id" field
  - Body contains "createdAt" timestamp

Format Reference

Keyword Purpose Example
Given Precondition / initial state Given the user is logged in
When Action performed When the user clicks "Submit"
Then Expected outcome Then a success message appears
And Additional step And the form is cleared
Scenario Test case title Scenario: Validate login form
Pro Tip

Include specific element identifiers (IDs, class names, or text) in your requirements for more accurate locator generation. Example: "click the button with id='submit-btn'"

How to Use Kade Test Gen

Follow these simple steps to generate production-ready test automation code:

1

Choose Your Input Source

Select from Word Document upload, GitHub repository, or direct text input. Each source works with the same test case formats.

2

Select Test Type

Choose UI Tests (Selenium), API Tests (Rest Assured), or Mobile Tests (Appium) based on your automation needs.

3

Configure Controls Panel

Set test category, coverage level, assertion strictness, and wait strategy. Enable/disable generation options as needed.

4

Set Advanced Options (Optional)

Expand Advanced Configuration to set base package name, application URL, or API base URL for your project.

5

Generate Tests

Click "Generate Tests" and wait for processing. Your test cases will appear in the Results section with full Java code.

6

Download or Copy Code

Each generated test has Copy and Download buttons. Copy code to clipboard or download as .java files for your project.

Control Panel Options Explained

Option Description
Test Category Tags tests as Smoke, Regression, Negative, Boundary, or Security for organization
Coverage Level Controls test thoroughness from Minimal (happy path) to Extensive (edge cases)
Assertion Strictness Loose (basic checks), Medium (standard), Strict (comprehensive validation)
Wait Strategy Implicit (simple timeouts), Explicit (condition-based), Smart AI (adaptive waits)
Negative Tests Generate tests for invalid inputs and error scenarios
Auto Assertions Automatically add appropriate assertions based on test context
Dynamic Elements Add retry mechanisms and stability checks for dynamic content
Reusable Utilities Generate helper methods and utility functions

Best Practices

Writing Effective Requirements

  • Be specific: Include exact field names, button labels, and expected values
  • One scenario per test: Keep test cases focused on a single behavior
  • Include test data: Specify actual values for inputs, not just descriptions
  • Define clear outcomes: State exactly what should happen after each action

Organizing Your Tests

  • Use consistent naming conventions (Feature_Scenario_Condition)
  • Group related tests together in your requirements document
  • Include preconditions for test independence
  • Use test categories (@Tag) for selective test execution
Integration Tip

Generated tests use the Page Object Model pattern. Place BasePage in your pages package and BaseTest in your tests package. Individual test classes extend BaseTest automatically.
